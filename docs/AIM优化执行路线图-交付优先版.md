# AIM优化执行路线图：交付优先版

## 一、路线判断

当前 AIM 系统已经具备内容生成能力，但还没有成为标准化交付后台。

因此，现阶段不是优先把 AIM 做成“更强的 AI 内容产品”，而是先把它做成：

> 员工能用、客户能交付、结果能沉淀的 AI 短视频市场部后台。

技术增强如 RAG、流式输出、发布自动化都重要，但不能放在第一优先级。当前第一优先级是跑通交付闭环。

## 二、四阶段路线

## 阶段一：上线交付版

### 目标

7 天内跑通第一个客户项目：

```text
客户项目
  ↓
知识资产
  ↓
AIM生成选题/脚本/拍摄交接单
  ↓
质量检测
  ↓
审核
  ↓
拍摄发布
  ↓
数据回填
  ↓
周复盘
```

### 为什么先做这个

因为你现在要成交和交付，不是做技术展示。

客户不会因为你有 RAG 付款，但会因为你能帮他把老板经验变成持续获客的视频系统付款。

### P0 开发任务

#### 1. 修上线阻塞

- [ ] 清理 `.env.example` 真实密钥。
- [ ] 重置 DeepSeek、TheRouter、OSS、数据库、JWT、管理员密钥。
- [ ] 把 Google Fonts 改成本地字体或系统字体。
- [ ] 修复 build。
- [ ] 修复影响上线的 lint。
- [ ] 配置生产 MySQL/MariaDB、Redis、域名、HTTPS。
- [ ] 创建管理员账号。

#### 2. 官网定位收束

把首页从泛 AI 工具改为：

> 帮传统企业搭建自己的 AI 短视频市场部

首屏建议：

```text
标题：
帮传统企业搭建自己的 AI 短视频市场部

副标题：
用 AIM 系统把老板经验、产品卖点、客户问题和成交案例，转化成可持续生产的选题、脚本、拍摄交接单和私域承接话术。

按钮：
预约系统诊断
领取《AI短视频市场部7步搭建法》
```

#### 3. 新增客户项目

新增 `ClientProject`，用于多客户交付隔离。

字段建议：

```text
id
userId
name
companyName
industry
ownerName
contactName
collaborationType: feishu | wecom | manual
offer
targetCustomer
dealPath
status: onboarding | active | paused | completed
startedAt
endedAt
createdAt
updatedAt
```

#### 4. 知识库绑定客户项目

`KnowledgeEntry` 增加：

```text
projectId
```

查询知识库时按：

```text
userId + projectId + status
```

避免不同客户知识混在一起。

#### 5. AIM 生成绑定客户项目

`AimGeneration` 增加：

```text
projectId
topicTitle
hotTopic
polishInstruction
shootingBrief
coverText
commentHook
privateDomainScript
workflowStatus
reviewNote
publishedAt
```

#### 6. AIM 增加拍摄交接单

新增输出格式：

```text
视频标题：
核心观点：
目标客户：
视频目标：涨粉 / 建信任 / 引流 / 成交
拍摄形式：口播 / 访谈 / 场景展示 / 混剪
建议时长：
脚本正文：
必拍镜头：
补充素材：
封面文案：
评论区引导：
私域承接话术：
事实风险提醒：
```

这是 AIM 从“写文案工具”变成“短视频市场部后台”的关键交付物。

#### 7. 增加内容状态流转

每条生成内容增加状态：

```text
draft
pending_review
client_confirming
ready_to_shoot
shooting
editing
ready_to_publish
published
reviewed
archived
```

员工通过状态推进交付。

#### 8. 质量检测嵌入 AIM

生成后自动检测：

- 是否像真人说话
- 是否符合 IP 档案
- 是否有前三秒钩子
- 是否有明确 CTA
- 是否适合拍摄
- 是否有事实风险
- 是否有成交承接

输出状态：

```text
不可提交
可优化
可提审
可拍摄
```

### 阶段一验收标准

- [ ] 用户能注册、登录、激活。
- [ ] 管理员能生成激活码。
- [ ] 能创建客户项目。
- [ ] 知识库能按项目录入。
- [ ] AIM 能按项目生成内容。
- [ ] AIM 能输出拍摄交接单。
- [ ] 生成结果能保存。
- [ ] 生成结果有状态。
- [ ] 质量检测能在生成后触发。
- [ ] 员工能按 SOP 跑完一次交付。

## 阶段二：生成质量版

### 目标

让 AIM 写得更准、更像老板、更适合成交。

### P1 开发任务

#### 1. AIM 对接三步流水线

当前系统存在：

- `aim-generator.ts`：AIM 页面使用的简单生成器
- `script-generator.ts`：更高质量的三步流水线

优化方向：

> AIM 页面生成视频脚本时，优先使用三步流水线。

三步逻辑：

```text
Meta 分析
  ↓
Script 生成
  ↓
Score 质量评分
```

#### 2. 候选文案对比

生成 2-3 个候选版本，让员工或你选择。

展示：

- 候选 A
- 候选 B
- 候选 C
- 吸引力评分
- AI 味评分
- 成交钩子评分
- 推荐理由

#### 3. Chat 素材萃取

把 Chat 模式从聊天改成：

> 老板经验访谈与素材萃取。

每轮对话自动提取：

- 产品卖点
- 客户痛点
- 成功案例
- 老板经验
- 差异化表达

并提供按钮：

```text
一键存入知识库
```

#### 4. 用户反馈回写

每条生成结果增加：

- 好内容
- 不满意
- 已复制
- 已采用

后续用于优化生成规则。

### 阶段二验收标准

- [ ] AIM 视频脚本质量明显优于旧版。
- [ ] 能展示多个候选。
- [ ] Chat 能提取结构化素材。
- [ ] 提取素材能一键入库。
- [ ] 生成记录能保存用户反馈。

## 阶段三：智能知识库版

### 目标

让知识库从“仓库”升级成“业务大脑”。

### 为什么不放 P0

RAG 很重要，但现阶段不是最急。

第一批客户知识库数据不会特别大，规则检索可以先撑住交付。

### P2 开发任务

#### 1. 规则检索

先不做向量数据库，先按以下规则召回知识：

```text
项目
分类
关键词
内容目标
行业
最近使用
高价值标记
```

#### 2. RAG 化

后续再做：

- Embedding
- Top-K 语义检索
- 相关性排序
- 高价值知识优先

#### 3. 高价值知识标记

当某些知识条目反复产生好内容，自动标记为：

```text
high_value
```

#### 4. 知识补全建议

当系统发现某类知识缺失时，提示员工补充：

```text
当前项目缺少成交案例，建议补充 2-3 个客户真实案例。
```

### 阶段三验收标准

- [ ] AIM 不再全量塞入知识库。
- [ ] 系统能优先引用相关知识。
- [ ] 高价值知识能被标记。
- [ ] 系统能提示员工补充缺失知识。

## 阶段四：发布闭环版

### 目标

从内容生产走向内容发布、线索承接和数据复盘。

### P3 开发任务

#### 1. social-auto-upload API 化

将当前独立 Python CLI 封装成服务。

但第一版不要全自动发布，先做：

```text
生成发布包
  ↓
员工确认
  ↓
半自动发布
```

#### 2. 发布日历

新增周视图：

- 日期
- 平台
- 标题
- 状态
- 负责人
- 发布时间

#### 3. 发布数据回填

先手动录入：

- 播放
- 点赞
- 评论
- 私信
- 加微
- 成交

#### 4. 私域承接

每条内容配套：

- 评论区置顶
- 私信回复
- 加微后欢迎话术
- 365 社群引导
- 咨询诊断引导

### 阶段四验收标准

- [ ] 每条内容有发布计划。
- [ ] 发布后能回填数据。
- [ ] 能生成私域承接话术。
- [ ] 能输出每周复盘。

## 三、原技术方案如何调整

### 原 P0：知识库 RAG 化

调整为 P2。

原因：重要但不紧急，先用项目隔离 + 规则检索。

### 原 P0：AIM 对接三步流水线

调整为 P1。

原因：提升质量重要，但上线交付版先解决流程和交付物。

### 原 P0：Chat 素材萃取

调整为 P1。

原因：很适合老板访谈，但不影响第一版上线。

### 原 P1：流式输出

调整为 P3 或后置。

原因：改善体验，但不是成交和交付关键。

### 原 P3：发布集成

保留为 P3。

原因：先不做全自动发布，先做发布包和数据回填。

## 四、第一版不要做

- 不做完整 CRM。
- 不做复杂任务管理。
- 不做全自动发布。
- 不做客户所有聊天记录同步。
- 不做员工直接调用 Codex。
- 不做大规模 SaaS 开放注册。
- 不做过早 RAG 重构。
- 不做打字机流式输出。

## 五、第一版必须做到

第一版只追一个结果：

> 员工能把一个客户的资料，用 AIM 稳定变成选题、脚本、拍摄交接单和复盘。

最小闭环：

```text
创建客户项目
  ↓
录入知识资产
  ↓
生成选题
  ↓
生成脚本
  ↓
生成拍摄交接单
  ↓
质量检测
  ↓
提交审核
  ↓
发布后回填数据
  ↓
周复盘
```

这个闭环跑通，你就可以开始卖企业陪跑。
