# AIM 产品定位与 Agent 优化思路

更新时间：2026-05-27

## 1. 当前判断

AIM 现在不应该被定义成“一个 AI 写文案网站”。

更准确的定位是：

> AIM 是传统企业搭建 AI 短视频市场部的 IP 营销全案后台，核心角色叫 AI内容总监。

客户买的不是网站本身，也不是某个按钮，而是：

- 把老板经验变成内容资产。
- 把产品卖点变成成交表达。
- 把客户痛点变成选题和脚本。
- 把内容生产变成员工可执行 SOP。
- 把 Codex、飞书、Obsidian、ClawBot、Hermes 等复杂能力封装成一个简单工作台。

所以产品第一版的核心标准不是“功能多”，而是：

> 一个普通员工拿到客户资料后，能不能每天稳定产出可拍、可发、可成交的内容。

## 2. 为什么别人要用 AIM

如果客户已经熟练掌握 Codex + 飞书 + Obsidian + ClawBot + Hermes，他可能不需要 AIM。

但真实目标客户大概率不是高阶 AI 玩家，而是：

- 传统企业老板。
- 新媒体负责人。
- 普通内容运营。
- 想做老板 IP 但没有方法的团队。
- 有飞书/企微，但不会把业务经验变成内容系统的公司。

他们的真实问题不是缺工具，而是缺一套能落地的业务流程：

- 不知道该录入什么资料。
- 不知道什么内容算好。
- 不知道怎么持续产出。
- 不知道员工每天该做什么。
- 不知道如何从内容走到私域咨询和成交。

AIM 的价值是把复杂能力翻译成业务动作。

底层可以是 Codex、飞书、Obsidian、ClawBot、Hermes。

前台必须是：

1. 新建 IP 营销全案。
2. 补齐客户资料。
3. 沉淀内容资产。
4. 生成/改写内容。
5. 质检。
6. 进入拍摄/发布/复盘。

## 3. 当前命名问题

当前系统里还有明显的“工具化/项目管理化”表达：

| 当前叫法 | 问题 | 建议叫法 |
|---|---|---|
| 客户项目 | 太泛，像普通项目管理 | IP营销全案 |
| 新建交付项目 | 不够产品化 | 新建IP营销全案 |
| AIM 内容生产 | 偏工具 | AI内容总监 |
| 进入客户项目 | 动作不清晰 | 进入全案 |
| 客户资料 | 太散 | 全案资料 |
| 项目名称 | 管理味重 | 全案名称 |

建议第一轮前台文案统一成：

> IP营销全案 / AI内容总监 / 全案资料 / 内容资产 / 质检 / 拍摄交接单

这样客户理解的是“我在搭一套营销系统”，不是“我在用一个写文案工具”。

## 4. AIM 是否属于 Agent

严格说，当前 AIM 还不是完整 Agent。

当前更准确的阶段是：

> AI内容总监 + 标准化工作流。

三层区别：

| 层级 | 特征 | AIM 当前状态 |
|---|---|---|
| 工具型 AI | 输入一段话，输出一段内容 | 已具备 |
| 工作流系统 | 按固定流程生成选题、脚本、朋友圈、公众号 | 已接近 |
| Agent 系统 | 给目标后能拆任务、调用工具、检查结果、推进状态 | 部分具备，未完整闭环 |

所以对外不建议说“我们有几十个 Agent”。

更合适的说法：

> AIM 是一套面向传统企业的 AI IP营销全案后台，内置 AI内容总监，负责改稿和脚本生成；选题、分发、质检、状态推进做成标准化工作流。

## 5. 第一版到底保留什么

第一版不需要多个 Agent。

原则：

> 前台一个 AI内容总监，后台几个明确工作流。

第一版只保留一个核心智能角色：

### 5.1 AI内容总监

目标：把老板原话、客户原文、产品卖点和客户痛点，改成能拍、能发、能成交的内容。

输入：

- 原始想法。
- 原文案。
- 老板口述。
- 选题。
- 客户资料。
- 修改要求。

输出：

- 改稿版本。
- 口播脚本。
- 前三秒钩子。
- 去 AI 味版本。
- 更适合老板表达的版本。
- 私域承接话术。

内部必须包含 5 个能力，不需要在前台都做成按钮：

- 开头优化：单独强化前三秒，用痛点、反差、利益或好奇打开。
- 文案结构优化：把内容改成问题、判断、案例、行动等更适合短视频的结构。
- 知识库注入：结合企业产品卖点、客户痛点、老板经验和项目案例。
- 对标文案改编：学习对标文案的开头、结构、节奏和转化设计，但不照抄表达。
- 长文转多场景：把公众号文案转成短视频脚本、朋友圈文案和社群运营文案。

### 5.2 选题工作流

目标：把业务资料变成可拍选题。

输入：

- 客户痛点。
- 产品卖点。
- 老板经验。
- 成交案例。
- 行业趋势。

输出：

- 短视频选题。
- 选题角度。
- 目标客户。
- 内容目的：涨粉、建信任、引流、成交。

选题工作流要支持垂类行业热点：

- 行业热点。
- 平台热点。
- 客户高频问题。
- 竞品/对标账号近期爆款。
- 企业自身案例和产品卖点。

第一版可以先人工输入热点或对标素材，后续再接自动抓取。

### 5.3 分发工作流

目标：把一条核心内容改造成不同渠道表达。

第一版只保留：

- 朋友圈。
- 公众号。
- 短视频标题/封面文案。

暂时不要扩展太多平台，否则复杂度会膨胀。

### 5.4 质检工作流

目标：判断内容能不能用。

检测维度：

- 开头吸引力。
- 人话程度。
- 逻辑完整度。
- 拍摄可行性。
- 成交承接。
- 事实风险。

输出：

- 评分。
- 问题清单。
- 修改建议。
- 是否可进入拍摄。

## 6. 第一版产品结构

建议系统只保留一条主线：

```text
IP营销全案
  -> 全案资料
  -> 内容资产库
  -> AI内容总监
  -> 质量检测
  -> 拍摄交接单
  -> 状态推进
```

对应到现有系统：

```text
ClientProject
  -> KnowledgeEntry
  -> AimGeneration
  -> workflowStatus
```

也就是说，现有数据库底层可以先不大改。

前台命名先改成更商业化：

- `ClientProject` 代码层仍可保留。
- UI 层统一叫“IP营销全案”。
- API 路径暂时不改，避免影响上线。

这是当前最稳的做法。

## 7. 首页应改成什么

当前首页问题：

- “今天要交付哪个客户？”方向是对的。
- 但“客户项目”还是弱。
- 应该强化“全案”和“市场部”的概念。

建议首页首屏改为：

> 今天推进哪个 IP 营销全案？

副标题：

> 第一版只保留一条主路径：全案资料、内容资产、AI内容总监、质检、拍摄交接。让员工每天按流程交付。

三个主按钮：

1. 新建 IP 营销全案。
2. 改一篇客户文案。
3. 生成一条短视频脚本。

## 8. 营销全案页应改成什么

当前 `/projects` 页面建议改为“营销全案”。

字段建议：

### 必填字段

- 全案名称。
- 公司/品牌。
- 行业。
- 目标客户。
- 核心产品/服务。
- 本阶段交付目标。

### 第二阶段再加

- 老板人设。
- 价格带。
- 成交方式。
- 客户常见异议。
- 过往成交案例。
- 竞品账号。

第一版不要把表单做太长。

## 9. AI内容总监应改成什么

当前 AIM 页面应该优先服务市场上最常见的需求：把公众号文案、长文、老板口述，转成短视频文案、朋友圈文案和社群运营文案。

下一步建议只做 3 个任务入口：

1. 改文案。
2. 写脚本。
3. 做质检。

短视频文案、朋友圈文案、社群运营文案应该作为第一版主输出。公众号文章可以作为输入来源，不要作为第一版核心输出。

用户路径：

```text
选择 IP营销全案
  -> 选择任务：改文案 / 写脚本 / 做质检
  -> 输入公众号文案、长文、老板口述或原始内容
  -> 输出结果
  -> 生成短视频脚本、朋友圈文案、社群运营文案
  -> 标记状态
```

## 10. 不建议第一版继续做的事

上线前不建议继续扩展：

- 自动发布。
- 视频生成。
- 热点追踪。
- 对标分析。
- 复杂 Agent 编排图。
- 多平台矩阵管理。
- 飞书/企微深度集成。

这些不是没价值，而是会分散第一版验证重点。

第一版要验证的是：

> 传统企业老板/员工是否愿意用 AIM 作为内容交付后台。

## 11. 可对外表达

短版：

> AIM 是帮传统企业搭建 AI 短视频市场部的 IP 营销全案后台，内置 AI内容总监。

销售版：

> AIM 不是一个 AI 写文案工具，而是一套 IP营销全案交付后台。它把公众号长文、老板经验、产品卖点、客户痛点和成交案例沉淀成内容资产，再由 AI内容总监转成短视频脚本、朋友圈文案和社群运营文案。

员工培训版：

> 你不用懂 Codex，也不用会复杂 Prompt。你只需要按流程补资料、选任务、审核结果，AIM 会帮你完成选题、脚本、改稿、质检和交接单。

## 12. 下一轮开发优先级

### P0：命名统一

- 客户项目 -> IP营销全案。
- 新建交付项目 -> 新建IP营销全案。
- AIM 内容生产 -> AI内容总监。
- 项目名称 -> 全案名称。
- 交付中的客户 -> 进行中的全案。

### P1：工作台任务收敛

- 保留：改文案、写脚本、做质检。
- 短视频脚本、朋友圈文案、社群运营文案作为主输出。
- 拍摄交接单变成结果后的二次动作。
- 隐藏复杂格式选择。

### P2：全案资料最小化

- 表单只保留 6 个字段。
- 其他资料放到“补充资料/内容资产库”。

### P3：AI内容总监与功能模块分层

前台不展示 Agent 列表。

后台只保留一个核心智能角色：

- AI内容总监。

以下能力不包装成 Agent，做成普通功能模块：

- 选题工作流。
- 分发工作流。
- 质检工作流。
- 状态推进工作流。

### P4：上线后再接飞书/企微/Obsidian

飞书、企微、Obsidian 不作为第一版前台卖点。

它们应该作为你的交付增强：

- 飞书：团队协作和客户资料收集。
- 企微：客户沟通和私域承接。
- Obsidian：长期知识资产沉淀。
- Codex：后台总协作大脑。
- ClawBot/Hermes：自动化管道。

客户看到的是 AIM，不是底层工具链。

## 13. 最终建议

不要把 AIM 做成“很多 AI 工具的集合”。

要把它做成：

> 一个传统企业可以真正执行的 AI IP营销全案系统。

产品第一版只解决一件事：

> 从客户业务资料到可拍可发可成交内容的标准化生产。

这件事跑通后，再去做自动发布、数据复盘、飞书企微联动和更复杂的后台协作。
