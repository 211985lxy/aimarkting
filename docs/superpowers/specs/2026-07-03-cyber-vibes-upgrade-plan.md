# Cyber Vibes 取长补短升级规划

> **对标对象**：Cyber Vibes AI Agent（13 个短视频文案智能体）
> **目的**：参考对方所有优势，制定 AIM 的升级规划，做到取长而不丢己。
> **核心原则**：不推倒重来，在现有架构骨架上挂肉；方法论作为知识资产沉淀，而非藏在 prompt 里。
> **创建日期**：2026-07-03

---

## 一、取长补短总览矩阵

把 Cyber Vibes 的 11 项可参考优势，逐一对照 AIM 现状，标出"长"还是"短"，给出融入落点。

| # | 对方优势 | AIM 现状 | 长/短 | 取长补短的落点 | 复用现有架构 |
|---|---------|---------|-------|--------------|------------|
| 1 | 按**内容场景**拆分智能体 | 一个超级 content_producer | 短 | 在 agent 内引入「内容场景模式」 | `CopyStructure`/`OpeningType` |
| 2 | **爆款方法论**提取与传递 | 竞品分析只出报告 | 短 | 竞品分析增加方法论文档输出 | `competitor-analysis` + 知识策略 |
| 3 | 三种**口播结构**显式切换 | 结构由 agent 自动决定 | 短 | 选题后提供「换结构」按钮 | `CopyStructure` |
| 4 | **投流转化文案** | 无 | 短 | 新增 traffic_conversion 场景 | `ContentGoalType` |
| 5 | **KOL 探店文案**+四要素方法论 | 无专用模板 | 短 | 新增 kol_explore 场景 + 知识条目 | 知识库 |
| 6 | **前采资料**批量整理 | persona 是交互式提问 | 短 | persona 增加「资料整理模式」 | `persona` agent |
| 7 | **爆款仿写**（跨行业逻辑迁移） | 改文案是同内容润色 | 短 | 改文案增加「仿写模式」 | `polishCopy` |
| 8 | **语言风格库**（50 种） | 改文案无风格选择 | 短 | 精选 10-15 种风格选择器 | `KnowledgeEntry` |
| 9 | **行业模板库**（20 示例） | IP Profile 向导无模板 | 短 | 向导增加「行业模板快速填充」 | `IpProfile` |
| 10 | **分批输入+确认式**交互 | 无 | 短 | 用于前采/知识批量导入 | 输入层 |
| 11 | 跨智能体**可传递文档** | 有 IP Profile+Wiki | 长 | 新增「爆款方法论」为第三文档 | `IpWikiPage` 模式 |

**关键洞察**：对方 11 项优势里，10 项是我们的"短"。但 AIM 的架构（结构化数据模型 + 知识策略层 + 三层内容架构）天然适合承载这些"短"。我们不需要推倒重来，而是"在现有骨架上挂肉"。

---

## 二、核心决策：内容场景化方式

**已确认采用方案 A：agent 内场景模式**（不拆 agent）。

在 `content_producer` 内引入 `ContentScenario` 枚举，每个场景绑专属 prompt + 知识策略 + 质检侧重。所有场景共享 content_producer 的质检、多模型路由、知识注入能力，不重复造轮子。

**理由**：
- 维护成本低，迭代快（场景 prompt 改动不需要动 agent 路由）
- 避免拆成 13 个 agent 带来的重复代码和一致性维护负担
- 与现有 `CopyStructure`、`OpeningType`、`ContentGoalType` 数据模型天然契合

## 三、三阶段 Roadmap

### 🚀 阶段一：高杠杆增强（7-10 天）

**目标**：用最小改动，把对方最值钱的"短"补上，立刻提升内容质量与精准度。

#### 特性 1.1：内容场景模式

对应优势：#1、#3、#4、#5

引入 `ContentScenario` 枚举：

```
ContentScenario:
  - ip_knowledge        → IP 知识型口播（专业信任）
  - entity_local        → 实体/本地获客（到店转化）
  - traffic_conversion  → 投流转化文案（强 CTA，3 秒抓人）
  - xhs_planting        → 小红书种草（素人感）
  - kol_explore         → KOL 探店（感官+信任+稀缺）
```

每个场景绑三样东西：
- **专属 prompt 块**：场景特定的开头/结构/CTA 指令
- **专属知识策略 tier**：复用现有 `aim-knowledge-strategy.ts`，新增 `scenario_traffic`、`scenario_kol` 等
- **质检侧重**：投流场景重点查 CTA 强度和开头 3 秒；探店场景重点查感官爆点完整度

**交互**：用户从前端 5 个场景卡片里选一个（或 agent 根据 IP Profile 自动推荐），生成选题和文案时按场景走专属逻辑。

#### 特性 1.2：口播结构显式切换

对应优势：#3

- 选题卡片上标注当前 `CopyStructure`，增加「换结构」按钮
- 三类语义映射：A 独白流（经历/故事/观点）/ B 结论先行（真相/判断/避坑）/ C 对话记录（提问者问、IP 答）
- 不重新生成选题，只换表达结构

#### 特性 1.3：语言风格选择器

对应优势：#8

- 改文案 Agent 增加「风格切换」
- 精选 12 种风格：犀利/幽默/克制/口语化/文艺/故事感/金句体/老板口吻/过来人/反常识/治愈/专业理性
- 风格定义存成 `KnowledgeEntry`（category: `style_guide`），改文案时可引用
- 与 AIM Chat Evolution 的隐式风格学习**叠加**：用户显式选 → 优先；没选 → 用学习到的偏好

---

### 🔗 阶段二：跨智能体联动（10-14 天）

**目标**：打通"竞品分析 → 爆款方法论 → 选题/文案"的价值传递链，这是和 Cyber Vibes 拉开差距的关键。

#### 特性 2.1：爆款方法论提取

对应优势：#2、#11

在竞品分析 Pipeline 增加一个输出步骤：

```
competitor-analysis（6 维分析）
    ↓ 新增
爆款方法论文档（结构化）:
  - 开头打法（怎么抓人）
  - 中段推进（叙事节奏）
  - 结尾收束（CTA / 情绪落点）
  - 爆点迁移清单（哪些能迁移到本 IP）
  - 适用场景标签
```

这份文档作为**第三种可传递文档**（现有：IP Profile、IP Wiki），新增 `IpWikiPage` 的 `pageType: viral_methodology`，AOT 编译后注入下游内容生成。

#### 特性 2.2：前采资料批量整理

对应优势：#6、#10

`persona` agent 增加「资料整理模式」：
- 支持「分批粘贴 → 回复收到 → 说开始整理」的确认式交互
- 输出：身份 / 人设 / 故事 / 性格 / 商业逻辑 / 内容素材 + **信息缺口补采建议**
- 整理结果直接写入 `KnowledgeEntry`（boss_experience / customer_pain 等），沉淀为知识资产
- 这一步的产物可以直接喂给定位策划官，形成「前采 → 整理 → IP 档案」的链路

#### 特性 2.3：爆款仿写模式

对应优势：#7

`polishCopy`（改文案）增加新模式：
- **润色模式**（现有）：同内容优化表达
- **仿写模式**（新增）：输入「爆款原文 + 目标行业」，做结构解构 + 跨域重建
- 仿写时强制要求用户填「标准行业信息格式」（6 项：身份 / 产品 / 客户 / 卖点 / 目标 / 字数），保证迁移质量

---

### 🏗️ 阶段三：体验完善（5-7 天）

**目标**：补齐用户引导层面的"短"，降低使用门槛。

#### 特性 3.1：行业模板库

对应优势：#9

IP Profile 创建向导增加「选行业模板快速填充」：
- 首批 12 个模板：餐饮 / 美业 / 健身 / 装修 / 汽车 / 教育 / 律师 / 中医 / 职场 / 情感 / 房产 / AI
- 每个模板预填行业、典型客户、常见卖点、内容目标
- 数据来源：从已有用户的 IP Profile 里统计高频模式 + 参考 Cyber Vibes 的 20 个示例
- 用户选模板后可任意修改，不是强制

#### 特性 3.2：分批输入能力下沉

对应优势：#10

把阶段二的"确认式输入"抽象成**通用能力**，不止前采用：
- 知识条目批量导入
- 竞品资料输入
- 长文案素材输入
- 实现：前端检测到长文本 → 提示「内容较长，建议分批发送」

## 四、明确不做（防过度设计）

| 不做项 | 原因 |
|--------|------|
| 短剧剧本创作 | 不同内容形态，赛道外 |
| 50 种语言风格全做 | 过度工程，12 种够用 |
| 拆成 13 个独立 agent | 维护成本高，方案 A 场景模式更优 |
| 抄"默认 Claude"的单模型策略 | 我们多模型路由是优势，不能丢 |

---

## 五、关键设计原则（确保取长而不丢己）

避免"学对方学丢了自我"：

1. **场景模式 ≠ 拆 agent**：所有场景共享 content_producer 的质检、多模型路由、知识注入能力，不重复造轮子。
2. **方法论作为知识资产沉淀**：Cyber Vibes 的方法论藏在 prompt 里（不可见、不可管理），我们做成结构化文档（可管理、可迭代、可复用）。
3. **显式选择 + 隐式学习叠加**：风格/场景用户显式选的优先，没选的用 AIM Chat Evolution 学习到的偏好兜底。
4. **不牺牲全链路优势**：任何场景模式都自动继承"选题 → 文案 → 质检 → 视频 → 发布"的完整链路。

## 六、升级前后能力对照

| 维度 | 升级前 AIM | Cyber Vibes | 升级后 AIM |
|------|-----------|-------------|-----------|
| 内容场景化 | 通用 | ✅ 5 场景 | ✅ 5 场景（agent 内模式） |
| 爆款方法论 | ❌ | ✅ | ✅（结构化文档） |
| 口播结构切换 | ❌ | ✅ ABC | ✅ ABC |
| 投流文案 | ❌ | ✅ | ✅ |
| 探店文案 | ❌ | ✅ | ✅（场景 + 知识） |
| 前采整理 | ❌ | ✅ | ✅（+ 知识沉淀） |
| 仿写 | ❌ | ✅ | ✅（+ 标准格式） |
| 风格选择 | ❌ | ✅ 50 种 | ✅ 12 种 |
| 行业模板 | ❌ | ✅ 20 种 | ✅ 12 种 |
| 全链路生产 | ✅ | ❌ | ✅（保留） |
| 四维质量门 | ✅ | ❌ | ✅（场景化侧重） |
| 知识体系 | ✅ | ❌ | ✅（+ 方法论文档） |
| 多模型路由 | ✅ | ❌ | ✅（保留） |

**结论**：升级后，AIM 在 Cyber Vibes 的全部优势项上对齐甚至超越（因为方法论结构化、质量门场景化），同时在对方没有的领域（全链路、质量门、知识体系、多模型）保持领先。

---

## 七、一句话定位

> **Cyber Vibes 是「13 个好用的文案工具」；AIM 是「一个懂你的 AI 内容生产系统」。**
>
> 升级方向不是"变成 Cyber Vibes"，而是**把它的方法论深度嫁接到我们的生产系统上**。
