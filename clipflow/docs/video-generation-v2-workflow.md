# 视频生成 V2 流程方案

## 1. 结论先行

是的，**有必要**在现有视频创建流程里引入“闪剪视频模板”选择，但不能把它和“视频结构模板”或“爆款文案模板”混成同一个概念。

这三层本质上分别解决三个不同问题：

- **视频结构模板**
  决定“这条内容按什么叙事结构展开”，例如清单归纳、认知闭环、共情代入。
- **爆款文案模板**
  决定“这条内容按什么营销打法去说服”，例如痛点直击、行业观点、限时优惠、教程拆解。
- **闪剪视频模板**
  决定“最终视频长什么样、怎么包装、怎么混剪、有没有画中画、标题栏、字幕风格、身份条、BGM、素材动效”。

当前 ClipFlow 把前两层做成了 UI 选择，但没有真正进入生产链；第三层虽然底层有能力，但没有暴露给用户，也没有接入到最终视频任务。

所以当前系统的问题不是“文案 prompt 还不够强”，而是**表达层和包装层都没有真正打通**。

## 2. 本次 review 的目标

本次 review 的目标不是“把现有四步流程再修饰一下”，而是明确新的视频生产中枢：

1. 用户先决定这条视频要**讲什么、怎么讲**。
2. 用户再决定这条视频要**长什么样、拿什么素材撑起来**。
3. 系统把 **结构模板 + 内容模板 + IP 档案 + 当前观点 brief + 热点上下文 + 闪剪视频模板 + 用户素材** 统一编排成一个可追踪、可复用、可评分的生产计划。
4. 闪剪最终生成的不是“把一句话念出来的视频”，而是“有结构、有包装、有素材支撑、有明确 CTA 的营销短视频”。

## 3. 当前系统的真实问题

### 3.1 结构没有进入生产链

`/create` 第一步的“选择视频结构”目前只是 UI 选择，`selectedStructureId` 没有被送进真实脚本生成，也没有被送进视频制作请求。

结果：

- 用户以为自己在选导演结构
- 系统实际上没有遵守这个结构
- 后续文案和视频都无法保证节奏一致

### 3.2 爆款模板没有进入真实脚本生成

当前创建页第 2 步使用的是 `mock/services.ts` 里的假模板和假文案生成器，而不是 `/api/templates` + `/api/scripts/generate` 的真实后端链路。

结果：

- 用户选中的“行业观点”“避坑指南”“开箱测评”等模板只是界面卡片
- 模板变量没有采集
- 模板不会真正参与 prompt 组装
- 三条候选文案本质上只是浅层句式拼接

### 3.3 用户当前视频观点没有被当成一等输入

IP 档案解决的是“你是谁”，不是“你这条视频今天要证明什么”。

当前流程缺少：

- 本条视频的核心观点
- 想说服谁
- 想强调什么证据
- 想引导什么动作
- 不想出现什么表达

结果：

- 文案会泛
- 文案会短
- 文案会像“行业通用开场白”
- 和用户真实意图脱节

### 3.4 闪剪视频模板能力没有暴露出来

底层已经接了：

- `GET /v1/clip/template`
- `GET /v1/clip/template/detail/{id}`
- `GET /v1/clip/image/template`

而且数据模型里也已经有：

- `shanjianStyleId`
- `videoType`
- `packRulesJson`
- `processRulesJson`

但创建页没有真正使用它们。当前视频创建仍然在走一个写死的默认 `styleId`。

结果：

- 用户无法选择不同包装风格
- 用户无法明确指定是否使用更重的混剪感
- 模板绑定的布局、字幕、BGM、封面、身份条都没有被系统化使用

### 3.5 用户素材没有成为“镜头语言”

当前流程里“素材”不是一个被认真设计的步骤。

但对营销短视频来说，素材不是装饰，而是证据：

- 门店环境
- 产品细节
- 客户案例
- 对比图
- 截图
- 资质证明
- 操作过程
- before/after

如果没有素材规划，数字人再会说，也只是“空口播”。

## 4. 闪剪能力梳理

## 4.1 与本方案最相关的闪剪接口

### A. 模板能力

- `GET /v1/clip/template`
  获取视频模板列表，按 `scene` 过滤：
  - `virtualman`
  - `realMan`
  - `oralMixCutting`
  - `newsMixCutting`
- `GET /v1/clip/template/detail/{id}`
  获取模板详情，包括画布尺寸和图层结构
- `GET /v1/clip/image/template`
  获取 AI 封面模板

### B. 最相关的视频生成接口

- `POST /v1/clip/video/virtualman_broadcast`
  数字人 + 文案 + 配音 + 素材 + 包装，适合主流营销视频
- `POST /v1/clip/video/custom_virtualman_broadcast`
  支持 `scenes[]`，适合逐段文案、逐段素材精细控制
- `POST /v1/clip/video/broadcast_mixcut`
  纯素材混剪 + 配音
- `POST /v1/clip/video/custom_broadcast_mixcut`
  纯素材混剪的场景级控制
- `POST /v1/clip/video/news_mixcut`
  新闻体风格
- `POST /v1/virtualman/video`
  纯数字人口播，不带包装，适合作为原始素材，不适合作为用户主流程默认产物

### C. 与“炫酷”直接相关的请求能力

闪剪视频接口支持这些关键字段：

- `styleId`
- `materials[]`
- `introduceCard`
- `packRules`
- `processRules`
- `structLayers`
- `speakerExtra`
- `subtitle`
- `scenes[]`（custom 接口）

这意味着我们完全可以让用户控制：

- 选哪个视频包装模板
- 要不要字幕
- 要不要标题栏
- 要不要身份栏
- 要不要背景音乐
- 用哪些图片/视频做混剪
- 哪些素材放在哪一段
- 哪一段需要强证据画面

## 4.2 关于“画中画”能力

可以做，但要分清边界。

闪剪没有一个显式叫“pictureInPicture=true”的通用字段。画中画更多取决于两件事：

1. **所选视频模板本身的布局能力**
   某些模板天生就是主画面 + 辅助素材框的画中画风格。
2. **是否使用素材混剪和自定义场景**
   通过 `materials[]`、`scenes[]`、模板布局和包装规则，能实现类似画中画、多窗口、证据插帧的效果。

所以正确产品表达不是“给用户一个画中画开关”，而是：

- 让用户选“视频包装模板”
- 让系统告诉用户这个模板支持什么表现方式
- 再让用户补对应素材

## 5. 新的视频生成目标

V2 的目标不是让用户“填完表单后得到一条视频”，而是让系统输出一条具备以下特征的营销视频：

1. **有结构**
   观众能感受到开场、展开、证据、收束、CTA 的节奏。
2. **有观点**
   不是一句空话，而是明确表达“我今天要让你相信什么”。
3. **有人设**
   文案口吻和用户的 IP 档案一致。
4. **有包装**
   不是裸口播，而是有模板风格、有字幕、有版式、有节奏。
5. **有证据素材**
   不靠嘴硬说，而是用图、视频、案例、截图撑起来。
6. **可追踪**
   最终视频能追溯它用了什么结构、什么内容模板、什么包装模板、什么素材。

## 6. 推荐的新流程

建议把现有“4 步”升级为“6 步”，但在 UI 上仍可包装成 4 个大阶段。

## 6.1 用户视角的 6 步流程

### 第 0 步：前置条件

先确保用户 IP 档案完整，否则不允许进入创作主流程。

必填：

- IP 名称
- 行业
- 主打内容/服务
- 目标受众
- 人设特征
- 表达口吻
- 可信背书
- CTA

### 第 1 步：选择视频结构模板（导演层）

这一步决定叙事骨架，不决定具体文案内容。

例如：

- 清单归纳法
- 认知闭环法
- 共情代入法
- 叙事弧光法
- 收束定调法

系统要产出一个 `structure blueprint`，包括：

- 开场钩子方式
- 中段展开方式
- 证据位数量
- 结尾收束方式
- 建议时长范围

### 第 2 步：选择爆款文案模板 + 填写本条视频 brief（编剧层）

这一步决定“说服打法”。

用户不能只点一张模板卡片，还必须填写模板要求的变量，以及本条视频的专属 brief。

应采集：

- 内容模板
- 模板变量
- 本条视频主题/观点
- 想说服谁
- 核心卖点或核心论点
- 证据素材方向
- 期望 CTA
- 是否蹭热点
- 不能出现的表达

这是本次流程改造里最关键的一步。

### 第 3 步：AI 生成文案并评分（内容引擎层）

不要直接“一次生成 3 条文案”。

建议拆成三段：

1. 先生成大纲
2. 再生成 3-5 条完整口播稿
3. 再做一次评分和重排

每条候选至少要有：

- 开场钩子
- 观点展开
- 证据句
- 行动号召

并且要满足建议字数，而不是一句话。

建议目标：

- 40-80 秒视频：`180-320` 字
- 15-30 秒视频：`80-160` 字

### 第 4 步：选择闪剪视频模板 + 素材编排（包装层）

这一步是新流程里必须新增的步骤。

这一步让用户决定：

- 用哪个闪剪官方模板
- 视频是偏口播包装，还是偏强混剪
- 是否使用门店图、产品图、客户案例图、视频片段
- 是否使用自定义 BGM
- 是否使用身份栏、标题栏、自动封面

系统要把这一步做成“视频包装设计器”，至少要有这三块：

#### 4.1 选包装模板

从闪剪模板列表中选择：

- 数字人口播包装模板
- 素材混剪模板
- 新闻体模板

并展示：

- 模板封面
- demo
- 适合场景
- 是否适合画中画/强素材表达

#### 4.2 选素材

允许用户从资产库中为当前视频选择：

- 产品图片
- 门店图片
- 证据截图
- 客户评价图
- 商品细节视频
- 真人实拍片段
- 背景音乐

#### 4.3 做素材与文案段落映射

最理想不是“丢一堆素材进去”，而是按文案段落映射：

- 开场段用什么素材
- 证据段用什么素材
- CTA 段用什么素材

如果用户不手配，系统可自动补默认推荐。

### 第 5 步：选择数字人 / 声音并生成

这一步只做“谁来讲”，不要再承担内容和包装决策。

最终提交时应带上：

- `scriptId`
- `structureId`
- `templateId`
- `shanjianStyleId`
- `videoType`
- `materials`
- `bgm`
- `packRules`
- `processRules`
- `avatarId / virtualmanId`
- `speakerId`

## 6.2 对外呈现的 4 个大阶段

如果你觉得 6 步太长，可以 UI 上包装成 4 个阶段：

1. **定表达**
   结构模板 + 内容模板 + brief
2. **出文案**
   AI 生成 + 评分 + 选稿
3. **定包装**
   闪剪模板 + 素材 + BGM + 画面策略
4. **出视频**
   数字人 + 声音 + 生成

这样既保持流程清晰，也不把不同决策层混在一起。

## 7. 推荐的后端生产链

## 7.1 生产对象不应再只有 scriptContent

当前 `/api/tasks` 的核心输入还是 `scriptContent`。

V2 应改为围绕一个更完整的 `VideoProductionPlan`：

```ts
type VideoProductionPlan = {
  ipProfileId: string
  structureId: string
  contentTemplateId: string
  contentGenerationRunId: string
  scriptId: string
  shanjianTemplateId: string
  shanjianStyleId: string
  videoType: string
  materials: MaterialItem[]
  bgmAssetId?: string | null
  packRules?: Record<string, unknown>
  processRules?: Record<string, unknown>
  avatarId?: string | null
  virtualmanId?: string | null
  speakerId?: string | null
}
```

最终视频任务是对这个 production plan 的执行结果，而不是对一段文案字符串的执行结果。

## 7.2 推荐的数据层扩展

建议新增或扩展这些对象：

### A. `VideoStructure`

存：

- `id`
- `name`
- `description`
- `openingRule`
- `bodyRule`
- `evidenceRule`
- `closingRule`
- `targetDurationSecMin`
- `targetDurationSecMax`

### B. `VideoCreativeBrief`

存本条视频意图：

- `goal`
- `corePoint`
- `targetAudience`
- `proofPoints`
- `cta`
- `hotTopic`
- `forbiddenPhrases`

### C. `VideoPackagingTemplate`

用于映射闪剪模板：

- `name`
- `scene`
- `shanjianTemplateId`
- `shanjianStyleId`
- `videoType`
- `supportsAvatar`
- `supportsPipLikeLayout`
- `supportsBgm`
- `defaultPackRules`
- `defaultProcessRules`

### D. `VideoProductionPlan`

用于串联脚本、模板、素材、数字人和视频任务。

## 8. 推荐的 prompt 设计

不要再只做“模板 + brief + IP 档案”。

应该按 6 层组装：

1. **IP 档案**
   你是谁，怎么说话，有什么可信背书。
2. **视频结构 blueprint**
   这条内容按什么节奏组织。
3. **内容模板 blueprint**
   这条内容按什么营销打法展开。
4. **当前视频 brief**
   今天到底想表达什么。
5. **热点上下文**
   是否借势以及如何借势。
6. **时长和成片约束**
   目标字数、必须有 CTA、必须有证据句、不能空泛。

建议大模型流程：

- 第 1 轮：生成脚本大纲
- 第 2 轮：生成 5 条候选
- 第 3 轮：按 rubric 评分，返回前 3 条

评分 rubric 至少包括：

- 结构符合度
- 模板贴合度
- IP 口吻一致性
- 观点清晰度
- 证据力度
- CTA 强度
- 热点融合度
- 字数是否落在目标区间

## 9. 闪剪模板在流程中的正确位置

答案不是“把闪剪模板放到最前面”，而是：

- **内容先于包装**
- **表达先于镜头**
- **结构和文案先定，再让包装去服务表达**

所以推荐顺序是：

1. 选结构
2. 选内容模板 + brief
3. 出文案
4. **再选闪剪模板**
5. 再配素材
6. 再生成视频

如果反过来先选闪剪模板，用户会在还没想清楚“我要说什么”之前就陷入 UI 风格选择，最后只能得到“看起来热闹，但信息空心”的视频。

## 10. 落地优先级

## P0：必须先做

1. 创建页接入真实 `/api/templates` 和 `/api/scripts/generate`
2. 去掉当前 mock 文案生成
3. 补模板变量表单
4. 补“本条视频观点 brief”输入
5. 保存 `scriptId / generationRunId / templateId`

## P1：本次方案核心

1. 新增“闪剪视频模板 + 素材编排”步骤
2. 接入官方闪剪模板列表和模板详情
3. 允许用户选择图片/视频/BGM
4. 把 `shanjianStyleId + videoType + packRules + processRules` 真正带入 `/api/tasks`

## P2：质量跃迁

1. 脚本生成改成“大纲 -> 候选 -> 评分重排”
2. 支持素材按文案段落映射
3. 高级模式接入 `custom_virtualman_broadcast`
4. 支持自动推荐哪些素材适合开场/证据/CTA

## 11. 验收标准

### 内容层

- 用户选择结构后，生成 run 中必须可追踪 `structureId`
- 用户选择模板后，必须填写模板变量
- 用户必须填写当前视频的核心观点或核心表达目标
- 候选文案不能是一句话，必须满足目标字数区间

### 包装层

- 用户能选择闪剪官方视频模板
- 用户能为当前视频选择图片/视频/BGM 等素材
- 系统能区分内容模板和视频包装模板
- 视频任务创建时带上真实 `styleId`

### 生产层

- `VideoTask` 可追溯到 `Script`
- `Script` 可追溯到 `ContentGenerationRun`
- `ContentGenerationRun` 可追溯到 `IP Profile + 内容模板 + 当前 brief`
- 成片可追溯到 `闪剪模板 + 素材清单 + 数字人 + 声音`

## 12. 最后判断

你要的方向是对的。

而且不是“可选增强”，而是 ClipFlow 从“能跑通”变成“真能交付客户价值”的必要升级。

如果不把闪剪视频模板和用户素材纳入生产链，系统最终产出的会一直更像：

- 一个会说话的数字人口播工具

而不是：

- 一个能自动做出营销感、包装感、证据感的视频生产系统

真正能形成质变的，不是只把 prompt 写长，而是把这三层彻底拆开并打通：

1. **结构层**
   决定怎么讲。
2. **内容层**
   决定讲什么。
3. **包装层**
   决定怎么演、怎么剪、怎么炫。

这才是 ClipFlow 下一版视频生成流程的正确中枢。
